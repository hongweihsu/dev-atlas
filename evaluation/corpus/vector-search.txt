DevAtlas creates an embedding vector from each normalized text chunk and stores it
with the embedding model name and dimension. This metadata prevents search from
comparing vectors produced by incompatible model configurations. At search time,
it embeds the query with the compatible model and asks PostgreSQL with pgvector to
rank active-version chunks by cosine distance. Smaller cosine distance means greater
cosine similarity.

Search results preserve document, version, chunk, ordinal, text, and character
offset provenance. The answer workflow bounds the selected context and maps cited
evidence back to those stored identifiers. A high similarity score alone does not
prove that the evidence answers the question, so retrieval quality must be measured
against reviewed relevance judgments.
